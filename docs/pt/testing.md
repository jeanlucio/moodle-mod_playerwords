# 🧪 Testes Automatizados

O PlayerWords inclui uma suíte PHPUnit cobrindo lógica de negócio, consultas ao repositório, web
services e conformidade com a Privacy API, além de uma suíte Behat cobrindo o jogo, a integração
com o PlayerHUD e os relatórios de ponta a ponta num navegador real. Todo push de CI executa a
matriz completa (Moodle 4.5 → 5.x, PostgreSQL e MariaDB).

As quatro classes `event/*.php` não aparecem na lista — o Moodle só as carrega sob demanda quando
o evento correspondente realmente dispara, então a instrumentação nunca chega a vê-las.

A cobertura de `hud_service` caiu em relação à medição anterior porque `get_available_quantity()`,
`get_item_name()`, `consume_items()` e `grant_items()` agora carregam cada uma uma checagem
`if (!self::is_installed())` que retorna um valor neutro — o caminho de fallback para um site
onde o `block_playerhud` nunca foi instalado ou já foi removido. Todo ambiente de dev e CI deste
plugin instala o `block_playerhud` junto, então esses quatro ramos só são exercitados por
`test_item_methods_return_neutral_values_when_not_installed()` num site que genuinamente não tem
o bloco; aqui o teste fica skipped. Os próprios métodos de `ai_word_generator` que chamam IA de
verdade (`call_ai()`, `call_core_ai()`, `generate_and_save()`...) são o outro gap deliberado:
cobri-los exigiria mockar as chamadas HTTP reais do `local_aihub`/`core_ai`, julgado não valer a
pena por ora.

cobrindo o jogo em si, a integração com o PlayerHUD, os relatórios voltados ao professor e a
barra de ferramentas/modais — áreas que um teste unitário PHPUnit não consegue exercitar
